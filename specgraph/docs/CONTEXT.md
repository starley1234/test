# Как устроен SpecGraph (хранилище + контекст)

Это не «ещё один RAG». Сначала **граф спецификации**, потом по желанию **вектор** и **нарезка сырых файлов**. Чанк — запасной ход, не главная сущность.

## Две задачи сервиса

1. **БД-двойник.** Что загрузили из файлов — лежит неизменно и находится по коду/связи.
2. **Сборщик контекста.** Из двойника собираем пакет под модель: слабую (мало символов, только связанные узлы) или сильную (шире hop, больше текста).

Пайплайны, UI, MCP — клиенты сборщика. Они не должны сами резать Word.

---

## Куда что кладётся

Исходный файл всегда копируется на диск: `data/uploads/<uuid>_имя`. Строка в `documents` указывает на этот путь. `raw_text` — извлечённый текст, **не правим**.

| Что увидели при загрузке | Таблица | Зачем |
|---|---|---|
| Карточка Word (Идентификатор + Содержание) | `requirements` | единица смысла, текущая ревизия `is_current` |
| «Источник требования», файла ещё нет | `requirements` + `extra.stub` | место в графе, текст позже |
| Изделие / состав | `products` + `parent_id` | дерево изделия |
| Связь (refines, applies_to, …) | `entity_relations` | типизированный граф |
| Приложение, записка, xlsx | `attachments` | файл, привязанный к требованию по имени/коду |
| Рисунок из Word или отдельный png | `illustrations` | схема; байты **на диске** |
| Файл без карточек (методика, описание, большой doc) | `document_chunks` | нарезка **только этого** сырого текста |
| Предложение правки LLM | `requirement_drafts` | не двойник, отчёт сотруднику |
| Вектор для поиска «похож на…» | `embeddings` | индекс поверх узлов, не вместо графа |

Старые формулировки: `requirement_revisions`. Пайплайн смотрит только `is_current`.

### Картинки: «диск + blob < 2 МБ» — что это было

Раньше картинка писалась **дважды**:

- всегда файл `data/media/<document_id>_<имя>` — это и есть хранение;
- плюс колонка `illustrations.blob` в SQLite, если меньше 2 МБ.

Большая схема **не терялась**: она на диске, отдаётся `GET /illustrations/{id}`. Blob в БД дублировал мелкие файлы и раздувал SQLite. Дальше: **только диск**, в строке таблицы — путь, подпись, тип, связь с документом/изделием. VLM читает файл по URL, не вставляем пиксели в текстовый промпт.

## Граф, а не мешок чанков

Узлы: документ, изделие, требование (в т.ч. stub), иллюстрация, приложение, при необходимости чанк сырого файла.

Рёбра (тип важен):

- изделие → изделие: `composed_of`
- требование → изделие: `applies_to`
- требование → более общее / источник: `derived_from` / `refines`
- требование → документ, который **упомянут** в тексте (даже если карточек в том файле нет): `depends_on` + `extra.kind=mention`
- документ/изделие → рисунок: `illustrated_by`

Векторный индекс вешается **на те же узлы** (код+текст требования, подпись схемы, чанк методики). Поиск «похоже» предлагает кандидатов; в промпт кладём не «топ-8 чанков из ниоткуда», а **подграф вокруг попадания** (родители, дети, упомянутый файл).

Это и есть комбинация: **явный граф + вектор как указатель**, не замена.

## Когда нарезать, когда нет

Карточка требования **уже единица**. Резать «Содержание» на 1200 символов — ломать смысл и плодить RAG.

Нарезаем **только** сырой файл без карточек (или очень длинный `raw_text` без структуры): методика, пояснение, приложение. Чанк знает `document_id` и смещение в двойнике. В контекст чанк попадает, если выбран режим с нарезкой **и** документ связан с seed-требованием (mention / attachment).

## Режимы сборки контекста (`mode`)

Параметр `POST /retrieval/context` и пайплайна.

| mode | Что кладём в пакет | Кому |
|---|---|---|
| `graph` (по умолчанию) | seed-требование целиком, родители/stub, атрибуты, подписи рисунков, соседи по hop. **Чанков нет.** | сильная модель, разбор одной карточки |
| `hybrid` | graph + несколько чанков **упомянутых** сырых файлов, укладка в бюджет символов | слабое окно, нужна методика/приложение |
| `chunks` | почти только чанки связанных документов + коды требований как якоря | поиск по «простыне» без карточек |

Бюджет: `CONTEXT_BUDGET_CHARS` (по умолчанию 10 000 символов). Слои по убыванию приоритета: seed → родители → (если hybrid/chunks) чанки связей → подписи схем → прочие требования коротко.

Сильная модель: `mode=graph`, больше `hop`. Слабая: `mode=hybrid`, маленький бюджет, один seed. Схема: отдельный вызов VLM по `GET /illustrations/{id}`, результат — короткий текст, его можно повесить атрибутом/черновиком, не гоняя картинку в каждый прогон.

## Поток загрузки (чтобы не потеряться)

```
файл на диск
  → извлечь блоки (заголовок / таблица / картинка)
  → если таблица-карточка → requirement (+ stub источника)
  → если нет карточек → document + chunks
  → картинки → media/ + illustrations
  → имя файла встречается в уже загруженных требованиях → ребро mention
  → по желанию embeddings на узлы
```

Ничего не выкидываем: нет карточек ≠ «файл бесполезен». Он документ в графе.

## Что сейчас мешает ясности (и что делать)

**Оставить.** Две иерархии + `entity_relations`. Двойник vs `requirement_drafts`. Stub. Картинки на диске. Mentions. Режимы context.

**Упростить / не развивать.**

- Не класть 20 000 символов приложения в `requirement_attributes` (`файл:…`) — дубль чанков/attachments, раздувает карточку. Атрибут = ссылка (`document_id` / имя), текст брать сборщиком.
- Не эмбеддить всё подряд при каждом index, если слот EMBED пустой — статус `parsed` нормален.
- Не плодить UI и пайплайны. Один сборщик, разные `mode`.
- Blob в SQLite не нужен.
- Alembic можно позже; сейчас `create_all`.

**Добавить по мере нужды (не раньше).**

- Явный `context_mode` в запросе (сделано).
- Чанки только для файлов без карточек (сделано).
- Очередь ревью 100+ карточек по одной (следующий приоритет из старого списка).
- Краткий текст «что на схеме» после VLM — узел/атрибут, не замена файла.

## Как пользоваться, не думая о внутренностях

1. Загрузить пакет файлов (`POST /index`) — и карточки, и «просто документы», и картинки.
2. Смотреть дерево `/tree`, карточку `/requirements/{id}` (родители, файлы, рисунки).
3. Для модели: `POST /retrieval/context` с `requirement_id` + `mode`.
4. Пайплайн вызывает тот же сборщик. Черновик правки — отдельно, в файл не пишется.
